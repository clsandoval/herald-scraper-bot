<locked-spike-decisions>
1. Scorer = positional surprisal -log P(ability | hero, gameMode, skill-index),
   add-0.5 smoothed, OWN pick excluded (count-1 / tot-1, like item PMI). First 12
   non-talent picks. Drop abilityId 0 and isTalent==True entries. Hero-pool filter:
   ability must appear in >= max(3, 1% of the hero's builds) or its events are
   dropped; a build with <6 in-pool picks is skipped. Per-player score = sum of
   top-3 DISTINCT-ability surprisals. 0.5x discount on the hero's ult when its
   first-pick index <= 5. SINGLE_DRAFT + RANDOM_DRAFT excluded from corpus stats
   AND scored 0.
2. Ults derived from corpus (rules.derive_ults): among abilities in >=30% of a
   hero's builds, the one with the highest median first-pick index, kept only if
   median >= 4. No external data.
3. Match aggregation mirrors item weirdness: players over NOTE_BAR accumulate
   (sum), else the single weirdest player carries. NOTE_BAR = p99 of all player
   scores, computed from THIS run's corpus (not hardcoded).
4. Receipt tag (tune.label): "ult as pick N" (ult index <=4), "never skilled ult"
   (ult absent & >=10 picks), "opened X x3" (first 3 picks identical). X = ability
   name last segment.

NEW LOCKED (mid-flight, from the user):
A. Ranked games only: discovery SQL gains `lobby_type = 7`. Consequence: the corpus
   becomes single-mode (ALL_PICK_RANKED), so the scorer's mode-keyed stats and its
   SINGLE_DRAFT/RANDOM_DRAFT exclusion list become no-ops — KEEP both anyway (cheap
   robustness, zero extra code; existing pre-purge rows and any future mode drift
   stay handled).
B. Duration: keep ONLY matches >= 50 minutes. Discovery predicate becomes
   `duration >= 3000` (replacing the old `< 1800 OR > 3600` band-skip); the
   enrich-time dur_boring() cut becomes `durationSeconds < 3000`.
</locked-spike-decisions>
